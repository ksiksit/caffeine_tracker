# 기능 현황 및 기획 로드맵

> 작성: 2026-09-05 · 대상: `captest1` (iOS thin-client) · 서버: `../server` (서버 기준 기능 목록: `../server/docs/features.md`, 2026-09-01)
> 목적: 현재 제공 기능을 화면 단위로 정리하고, **기존 기능 개선안**과 **신규 기능 후보**를 우선순위와 함께 기록한다.
> 앱의 목적은 **수면의 질 향상**이고, 수단은 카페인 섭취 데이터와 수면 데이터로 인사이트를 제공하는 것이다.
> 현황은 2026-09-05 코드(`feat/client-server-phase1`)를 직접 읽고 정리했다.

## 0. 한눈에 보기

앱이 지금 답하는 질문은 세 가지다.

| 탭 | 답하는 질문 | 근거 데이터 |
|---|---|---|
| 홈 | "지금 커피 마셔도 되나?" | 서버가 계산한 잔류량·마감시각 |
| 수면 분석 | "어젯밤 어떻게 잤나?" | HealthKit 원시 샘플 → 서버 병합·요약 |
| 내 학습 데이터 | "내 반감기는 얼마인가?" | 취침 시 잔량 + SOL 베이지안 학습 |

비어 있는 질문은 **"그래서 카페인이 내 잠에 실제로 어떤 영향을 줬고, 내일은 뭘 바꿔야 하나?"** 이다.
학습 대시보드가 보여주는 R²·RMSE는 모델 통계이지 사용자 언어의 인사이트가 아니며, 인사이트를 행동으로 잇는 장치(알림·위젯)도 없다.
이 문서의 개선안·신규 후보는 이 구멍을 메우는 방향으로 골랐다. 추천 착수 순서는 §4.

### 1.7 앱 실행 시 자동 흐름 (현재)

```text
앱 시작 → 세션 확인 → ContentView.task
           ├─ 설정 로드(서버 → 로컬 미러)
           └─ HealthKit 권한 있으면 수면 7일 업로드 + 요약 조회
홈 진입   → /api/caffeine/today (잔류량·마감시각)
학습 탭   → /api/learning/run + /api/learning/dashboard   ← 탭을 열지 않으면 학습이 실행되지 않음
```

## 4. 추천 착수 순서

발표 임팩트 × 구현 비용 × 기존 구조 적합성 기준. 앞 번호일수록 먼저.

| 순서 | 항목 | 왜 이 순서인가 | 범위 | 예상 규모 |
|---|---|---|---|---|
| 1 | §2 (1) 수면 탭에 SOL + 취침 잔량 표시 | 인사이트의 최소 단위. 반나절짜리인데 "원인과 결과"가 처음으로 한 화면에 들어옴 | 앱 | 소 |
| 2 | §2 (2) 학습 자동 실행 위치 이동 | 관측이 안 쌓이면 뒤의 모든 인사이트가 비어 있음 | 앱 | 소 |
| 3 | §2 (3) 미연결 상태 처리 + today 캐시 | "지금 OK" 오표시 제거. 캐시가 위젯의 기반 | 앱 | 소 |
| 4 | §2 (20) 차트 취침 후 위험 영역 판정 수정 | 3과 같은 화면·같은 파일. 미연결 처리와 함께 손대면 홈이 "틀린 답을 주는" 경우가 한 번에 정리됨 | 앱 | 소 |
| 5 | §3.2 마감 알림 (= §2 (5)) | 설정에 자리 있음, 서버 변경 없음, 데모 임팩트 큼 | 앱 | 중 |
| 6 | §2 (19) `.safeAnytime` 도달 조건 재검토 | 신호등 4단계 중 하나가 기본 설정에서 절대 뜨지 않음. 작은 변경이지만 서버 `calc`와 클라 미러를 같이 고쳐야 해 앱 단독 범위에서는 빠짐 | 서버 `calc` + 앱 | 소 |
| 7 | §3.1 상관 리포트 + 그룹 비교 | 앱 목적의 본체. 서버 `domain/insight` 신설이 아키텍처 이야기와도 맞음 | 서버 + 앱 | 대 |
| 8 | §3.2 위젯 | 3의 캐시 재사용. 발표 시연에서 가장 눈에 띔 | 앱 | 중 |
| 9 | §2 (4) 신규 기록 섭취 시각 선택 | 데이터 정확도. 작은 변경 | 앱 | 소 |
| 10 | §3.3 아침 체크인 | Watch 없는 심사 환경에서도 학습 시연 가능 | 서버 + 앱 | 중 |
| 11 | §3.3 교란 요인 태그 | 모델 타당성 강화 | 서버 + 앱 | 중 |
| 12 | §2 (10) / §3.1 동적 취침 시각 | 마감 시각 개인화의 완성 | 서버 + 앱 | 중 |

**1차 범위 제안(앱 단독, 서버 변경 없음)**: 1 → 2 → 3 → 4 → 5 → 9. 이 여섯 개가 끝나면 서버 없이도 "SOL이 보이고, 학습이 매일 돌고, 오프라인에도 안전하고, 차트가 위험을 과장하지 않고, 마감 전에 알려주는" 앱이 된다.
**2차 범위(서버 동반)**: 6 → 7 → 8 → 10. 6은 규모가 작지만 서버 `calc`를 건드려야 해서 여기에 둔다. 리포트가 캡스톤의 핵심 산출물이므로 서버 `insight` 도메인 설계를 먼저 잡는다.

## 6. 미결 사항 · 확인 필요

- 프리셋 사이즈·샷 옵션(§2 (12))은 **카페인 mg 출처 검증** 후에만. 임의 값 금지.
- 건강 상태 복수 선택(흡연 + 경구피임약 등)은 승수 조합의 약리학 근거를 확인하기 전까지 보류. multiplier 자체는 변경 금지.
- 아침 체크인의 주관 SOL 관측 분산 값(모델 파라미터)은 서버 `calc`에서 정하고 골든 테스트에 포함.
- Apple Watch 없는 심사 환경의 시연 시나리오: 체크인(§3.3) 또는 시드 데이터 중 무엇으로 갈지 결정.
- 서버 스케줄러 학습(§2 (2) 2단계)은 사용자 타임존을 서버가 알아야 함(`tz` 저장 필요).
